# MacIrland Panel 精简改造需求文档

## 文档信息
- 日期：2026-04-09
- 状态：草案
- 目标版本：下一轮 panel UI 收敛
- 设计方向：`B. 介入处理优先`

## 1. 背景
当前 MacIrland panel 已经具备较完整的信息层次：
- 顶部 header
- 焦点卡片 / island 卡片
- overview 总览卡
- session 列表
- session 详情
- reply 输入
- diagnostics 诊断区

这套结构对“展示能力完整性”是有帮助的，但对当前产品阶段来说仍然偏重：
- 打开 panel 后，用户需要先扫过多块内容，才能判断“现在需不需要我介入”
- 总览、品牌表达、诊断信息占据了较高的视觉权重
- 真正最重要的动作链路
  - 谁在等我
  - 当前该回复什么
  - 我现在能点哪个动作
  还没有被提升到第一优先级

本次改造的目标不是“做得更炫”，而是把 panel 收敛成一个更像“介入工作台”的界面：用户打开后可以迅速判断是否需要处理，并在最短路径内完成一次回复或 quick action。

## 2. 核心目标
### 2.1 主目标
把 panel 精简成一个“介入处理优先”的工作区，只保留用户立即决策和立即操作所需的信息。

### 2.2 具体目标
1. 用户打开 panel 后，在 3-5 秒内判断是否需要处理某个会话。
2. 如果某个会话正在等待用户输入，用户应在不滚动或少量滚动的前提下直接看到：
   - 当前任务是什么
   - 为什么在等我
   - 我可以怎么回
3. 默认界面不再把 diagnostics、全局总览、装饰性摘要放在高优先级区域。
4. 保留工程排障能力，但改成低优先级、按需展开，而不是默认展开。

## 3. 非目标
本轮不做以下事情：
- 不重写 observation / state / session matching 逻辑
- 不做新的 reply bridge 持久化能力
- 不扩大 Codex / Gemini 真机接入范围
- 不做复杂动画
- 不做全新的多窗口或多栏布局

## 4. 用户场景
### 场景 A：有会话正在等用户输入
用户打开 panel，应该立刻看到：
- 当前最需要处理的会话
- 当前状态（等待输入 / 失败 / 需关注）
- 一条明确的操作提示
- 快捷回复按钮
- 自由输入框

用户不需要先经过 overview、品牌介绍、诊断区，才能进入处理动作。

### 场景 B：有运行中的会话，但暂时不需要用户输入
用户打开 panel，应该快速知道：
- 当前是否有活跃任务
- 最重要的那个任务在做什么
- 最近一次活跃时间

这时 panel 可以更安静，不需要把 reply 区和长 timeline 占满首屏。

### 场景 C：没有可识别会话
用户打开 panel，应该优先看到：
- 为什么为空
- 下一步怎么做

而不是一整块重量级 diagnostics 先扑到脸上。

### 场景 D：识别失败 / 权限异常
用户需要排障时，仍然应该能看到 diagnostics。
但 diagnostics 应该是“明确需要时再看”，不应默认成为主内容。

## 5. 设计原则
### 5.1 介入优先，而不是总览优先
当前 panel 更像一个“状态大盘”。改造后应该更像“处理台”。

默认首先回答的问题应是：
- 现在谁在等我？
- 我该点哪里？

### 5.2 一个主焦点，多个次要对象
同一时刻只突出一个主会话。

其他 session 应退到辅助列表，不和主会话争抢视觉注意力。

### 5.3 默认只展示可行动信息
没有直接支持当前决策和动作的信息，一律降级：
- 删除
- 折叠
- 缩小
- 延后显示

### 5.4 工程信息保留，但不抢首屏
diagnostics 仍然保留，但默认收起或缩成一行摘要。

## 6. 方案比较
### 方案 A：保留现有结构，只缩视觉体积
做法：
- 各区块继续保留
- 通过缩小字体、间距、卡片高度来“看起来更简洁”

优点：
- 改动小
- 风险低

缺点：
- 信息结构本身没有改变
- 用户仍然需要扫过很多区块
- 本质上只是“压缩”，不是“精简”

### 方案 B：介入处理优先工作台
做法：
- 把当前最重要的 session 提升为主工作区
- 将 reply / quick action 提升到主区
- 把 session 列表压缩成辅助导航
- 把 diagnostics 改成按需展开
- 移除不直接服务当前操作的 overview / 大摘要卡

优点：
- 与当前产品阶段最匹配
- 最能缩短“看到问题 -> 立即处理”的路径
- 用户心智清晰

缺点：
- 比单纯缩样式改动更明显
- 需要重新梳理 panel 内容层级

### 方案 C：排障优先控制台
做法：
- 保留 diagnostics 的高可见度
- 将 panel 继续做成工程视角工具面板

优点：
- 对开发阶段排障方便

缺点：
- 不符合这次“只保留必要信息”的目标
- 对普通使用场景过重

### 推荐方案
采用方案 B：`介入处理优先工作台`。

原因：
- 用户已经明确选择“介入处理优先”
- 这也是当前 panel 信息精简最有价值的方向

## 7. 目标信息架构
改造后的 panel 结构建议如下：

1. 极简 header
2. 主会话工作区
3. 辅助 session 列表
4. 可折叠 diagnostics

### 7.1 极简 header
保留：
- 品牌名 `macirland`
- 刷新按钮
- 一句极短状态摘要

删除或缩小：
- 多个 summary chips
- “会话数 / 待关注 / 本地观察”这一类全局统计

目标：
- header 只承担识别和刷新，不承担信息承载

### 7.2 主会话工作区
这是 panel 的核心。

需要保留：
- 会话标题
- 当前状态 badge
- 一句 summary
- 一句 primary guidance
- quick actions
- 自由输入框
- 最近 1-3 条关键 timeline

需要调整：
- 当前“任务摘要卡 + timeline + 快捷回复 + 自由输入”保留，但重新组织成一个连续工作区
- timeline 不再默认完整展开，只保留最近关键节点
- reply 入口上移，放到更靠前的位置

需要删除或合并：
- 单独的 island/compact hero 卡
- 冗余的状态 chips
- 不直接帮助当前处理的重复描述

### 7.3 辅助 session 列表
session 列表从“信息卡片 feed”降级为“导航列表”。

保留：
- 标题
- 状态
- 标题/摘要
- 最近活跃时间
- 是否等待处理

缩小：
- 每个 row 的高度
- chip 数量
- confidence 展示

删除：
- 非必要 chip，例如置信度百分比默认不显示
- 多余的模型 / 终端 / 时钟全量并列展示

建议每行只保留：
- 状态点/图标
- 会话标题
- 一句短摘要
- 右侧状态或等待标识

### 7.4 可折叠 diagnostics
diagnostics 默认折叠，只显示一行系统状态摘要，例如：
- 正常读取中
- 权限异常
- 识别失败，可展开查看

仅在以下情况展开详细内容：
- 用户手动点击“查看诊断”
- 当前 observation blocked
- 当前没有会话且有 reader 失败

保留：
- reader 结果
- raw observation
- evidence

但要求：
- 默认不占据主滚动区域的大面积空间

## 8. 逐项保留 / 删除 / 缩小清单
### 8.1 保留
- header 中的品牌名
- refresh
- 主会话标题与状态
- primary guidance
- quick actions
- draft reply 输入框
- session 列表
- diagnostics 能力

### 8.2 删除
- overview 总览卡
- 独立的 island compact 卡
- 默认展开的大块 diagnostics
- 默认展示的过多全局统计 chips

### 8.3 缩小
- header 高度
- session list row 高度
- timeline 默认展示条数
- metadata chips 数量
- 诊断信息默认占位

## 9. 关键交互要求
### 9.1 默认焦点选择
如果存在“等待用户输入”的 session：
- 默认选中它
- 主工作区直接展示它

否则：
- 选中当前优先级最高的 session

### 9.2 主工作区优先级
主工作区内的内容顺序应调整为：
1. 标题 + 状态
2. primary guidance
3. quick actions
4. 自由输入
5. 最近关键 timeline

而不是先让用户读完整摘要、完整历史，再看到回复入口。

### 9.3 timeline 折叠
默认只展示最近 3 条关键记录：
- 状态变化
- 用户操作
- 回复成功/失败

若用户需要，可展开“查看完整历史”。

### 9.4 diagnostics 折叠
默认只显示一行摘要和一个展开入口。

## 10. 视觉要求
### 10.1 更轻
主面板不再堆叠太多同权重卡片。

### 10.2 更直接
主工作区要一眼看出“这里可以操作”。

### 10.3 更克制
减少 chips、减少大面积辅助文案、减少重复状态表达。

## 11. 成功标准
改造完成后，应满足以下标准：

1. 首屏不再出现 overview 总览卡。
2. 首屏不再默认展开大块 diagnostics。
3. 用户打开 panel 后，不滚动就能看到主会话的 quick actions 和输入框。
4. 当存在等待输入会话时，用户不需要先点击列表再进入回复。
5. session 列表的信息密度下降，但仍能完成切换。
6. diagnostics 仍可访问，不丢失工程排障能力。

## 12. 实施建议
建议分两刀做：

### 第一刀：信息结构收敛
- 删除 overview 卡
- 删除 island compact 卡
- 把 reply 区提到主工作区上半部
- 把 diagnostics 改成折叠摘要
- 压缩 session list row

### 第二刀：视觉细化
- 进一步缩小 header
- 精简 chips
- 调整 timeline 默认折叠方式
- 优化空态与错误态文案

## 13. 需要确认但不阻塞起稿的点
以下问题当前先按默认假设处理：

1. 是否需要完全移除 timeline，而不是只折叠
   - 默认假设：保留，但只显示最近 3 条

2. session 列表是否需要保留二级摘要
   - 默认假设：保留一句短摘要

3. diagnostics 是否需要记住展开状态
   - 默认假设：本轮不做持久化，只做本次运行内展开状态

## 14. 推荐结论
本轮 panel 精简应以“介入处理优先”作为唯一主线：
- 让主会话成为主工作区
- 让回复动作成为首屏重点
- 让其他信息全部退为辅助

如果只能做一件最重要的事，就做这件事：

把 panel 从“状态展示面板”收成“等待用户时可立即介入的回复工作台”。
